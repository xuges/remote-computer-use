# remote-computer-use v0.1.0

首个版本，为 AI Agent 提供统一的远端桌面截图和键鼠操作命令。与 remote-shell 独立互补：remote-shell 执行远程命令、传输文件，本项目通过 VNC / RDP 操作 GUI。本机后台运行，不显示远端桌面窗口。

## 功能

- 两个 Go CLI：连接管理，以及截图、点击、移动、拖拽、滚轮、组合键、文本输入。
- 支持 Linux VNC、Mac VNC/ARD 与 Windows RDP；文本支持中文和 emoji，实际输入效果仍取决于远端应用和输入法。
- 通过 `go:embed` 内嵌原生运行库，首次使用释放到私有缓存；运行时无需安装 Go、FreeRDP 或 libgvnc。
- 离线安装、私有 TOML 配置、脱敏输出；CLI 与后台会话使用带令牌的回环 HTTP。
- 提供 Codex、OpenCode、Claude Code 共用 Skill 和安装入口。

## 安装包

每个包附带同名 `.sha256` 校验文件、安装器、配置示例、文档、Skill 和第三方许可资料。

项目自身采用 MIT，第三方代码不重新许可。另提供 `remote-computer-use-0.1.0-sources.tar.gz` 及其校验文件，包含对应原生库源码、发行版补丁、构建配方和项目源码；源码包与二进制放在同一 Release。

| 文件 | 本机要求 |
| --- | --- |
| `remote-computer-use-0.1.0-linux-amd64.tar.gz` | Linux x64，glibc 2.35+ |
| `remote-computer-use-0.1.0-linux-arm64.tar.gz` | Linux arm64，glibc 2.35+ |
| `remote-computer-use-0.1.0-darwin-arm64.tar.gz` | Apple Silicon，macOS 15.0+ |
| `remote-computer-use-0.1.0-windows-amd64.zip` | Windows x64，已在 Windows 10 22H2 验证 |

校验并解压后，Linux/macOS 执行 `./install.sh`，Windows 执行 `powershell -File .\install.ps1`。可选安装 Agent Skill；将命令目录加入 PATH，填写 `~/.remote-computer-use/config.toml`，执行 `remote-computer-ctl doctor` 后连接。运行包无需管理员权限，远端仍需启用 VNC / RDP 服务。

## 已知风险与限制

- **macOS 未公证：** 包仅采用 ad-hoc 签名，未完成 Developer ID 签名和 Apple 公证。终端安装运行已通过；浏览器下载的隔离属性可能触发 Gatekeeper，相关安装路径尚未验收。
- **Windows Defender：** EXE 未签名，新解压文件可能被 ASR 阻止启动，表现为“拒绝访问”。VNC 功能测试通过不意味着所有机器都能直接安装。安装器不会修改系统防护策略。
- **Linux ARM64：** 已完成 QEMU 验证，尚无实机验收；Linux 包不支持 musl/Alpine。
- Apple ARD 水平滚动暂返回 `UNSUPPORTED`；Windows 双轴滚动请分成两条单轴命令。
- Windows 本机回连自身 RDP 曾返回 `AUTH_FAILED`；其他 RDP 场景通过不能替代该场景验收。企业域/SSO、VNC X509 和所有平台交叉组合未完整覆盖。
- 截图不叠加光标，不提供剪贴板文本输入、跨命令持续按键或远端 HTTP API。
- 三个 Agent 的 Skill 安装和格式已验证，客户端自动发现与实际执行仍待联调。

Windows 使用不带图像加载器的最小 gdk-pixbuf 构建，移除了不需要的 TIFF/JBIG 依赖链；最终包包含 32 个原生库。Go 依赖、原生库许可和源码来源保留在包内，支持通过 `REMOTE_COMPUTER_LIB_DIR` 替换 ABI 兼容的修改版动态库。

静默仅表示本机不打开窗口，远端用户可能看到鼠标与应用变化。操作成功后应再次截图确认应用状态。

从早期 Unix socket 开发版升级时，先用旧 `remote-computer-ctl` 断开连接，再替换两个 CLI。当前 HTTP 接口不兼容旧 worker。

详细操作和测试边界见仓库 README、安装文档、验证记录及 Windows ASR 分析。GitHub 构建工作流的实际结果以 Actions 记录为准，本地验证不等同于 CI 通过。
